Solution

  1. Connect to the shared data_jobs DuckDB database from your terminal 
    duckdb md:data_jobs
  2. Run a query to calculate a consolidated final_salary by prioritizing yearly averages, then hourly rates scaled to an annual value, while providing a default backup value. 
    SELECT 
    job_id,
    COALESCE(
        NULLIF(salary_year_avg, 0), 
        NULLIF(salary_hour_avg, 0) * 2080, 
        50000
    ) AS final_salary
FROM 
    job_postings_fact;

Expected Outcome

Explanation

  • Connect to data_jobs: duckdb md:data_jobs opens a DuckDB session pointing at the shared data_jobs database so all queries run against that dataset.
  • Handling Zeros with NULLIF:

    The NULLIF function is applied to both salary_year_avg and salary_hour_avg. This converts any 0 values in the dataset into NULL. This step is essential because COALESCE skips NULL values but would treat a 0 as a valid entry, which would lead to incorrect salary reporting.

  • Normalizing Salary Calculations:
    • The query first attempts to use the existing salary_year_avg.
    • If that is missing, it takes the salary_hour_avg and multiplies it by 2080 (representing standard full-time annual hours) to estimate a yearly salary.
    • If both values are missing, it defaults to a standard value of 50000.
  • Consolidating Data with COALESCE:

    The COALESCE function acts as a priority list, returning the first non-null result from its arguments. This allows us to create a single, clean final_salary column from multiple potential data sources.
