Solution

  1. Connect to the shared data_jobs DuckDB database from your terminal 
    duckdb md:data_jobs
  2. Run a query to retrieve job IDs and provide a default value for missing schedule types using the COALESCE function. 
    SELECT 
    job_id,
    COALESCE(job_schedule_type, 'Not Specified') AS schedule_info
FROM 
    job_postings_fact;

Expected Outcome

Explanation

  • Connect to data_jobs: duckdb md:data_jobs opens a DuckDB session pointing at the shared data_jobs database so all queries run against that dataset.
  • Identify Data Source: The FROM clause specifies the job_postings_fact table, which contains the primary records for job listings.
  • Handle Null Values: The COALESCE function is utilized to provide a fallback value for the job_schedule_type column.

    In data engineering, handling NULL values is critical for clean reporting. The COALESCE function checks the job_schedule_type; if the value is NULL, it returns the string 'Not Specified'. If the value is not null, it returns the original value.

  • Column Selection and Aliasing: The SELECT statement defines which data to display in the final result set.
    • job_id: Included to uniquely identify each job posting record.
    • AS schedule_info: This renames the output of the COALESCE function to schedule_info, making the resulting dataset more readable and descriptive for end-users.
