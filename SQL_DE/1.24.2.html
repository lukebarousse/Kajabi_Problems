Solution

  1. Connect to the shared data_jobs DuckDB database from your terminal 
    duckdb md:data_jobs
  2. Create the job_skill_priorities table and populate it with active job skills by joining the skills_job_dim and priority_skills tables. 
    CREATE TABLE main.job_skill_priorities ( job_id INT, skill_id INT, skill_name VARCHAR(50), priority_lvl INT, status VARCHAR(20) );

    INSERT INTO main.job_skill_priorities (job_id, skill_id, status) SELECT sjd.job_id, sjd.skill_id, 'ACTIVE' FROM data_jobs.skills_job_dim AS sjd INNER JOIN staging.priority_skills AS ps ON sjd.skill_id = ps.skill_id;

Explanation

  • Connect to data_jobs: duckdb md:data_jobs opens a DuckDB session pointing at the shared data_jobs database so all queries run against that dataset.
  • Create Table (DDL):

    We begin by defining the structure of the new table main.job_skill_priorities using a CREATE TABLE statement. This establishes the schema and data types for the columns that will hold our processed data, including job_id, skill_id, and status.

  • Data Insertion (DML):

    The INSERT INTO statement specifies which columns in the destination table will receive data. We then use a SELECT subquery to pull and transform data from existing tables to populate these columns.

    • Filtering via INNER JOIN: We perform an INNER JOIN between data_jobs.skills_job_dim and staging.priority_skills on the skill_id column. This ensures that only skills explicitly listed in the priority staging table are added to our new table.
    • Literal Values: In the SELECT clause, we include the hardcoded string 'ACTIVE'. This assigns the same status value to every row inserted during this operation, documenting the current state of these records.
